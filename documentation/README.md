## Ray Verify
AI-assisted screening of patient-acquired and synthetic chest X-ray images
Ray Verify is a research prototype that helps medical-imaging research data curators screen chest X-ray images by estimating whether an image is patient-acquired or synthetic. It uses transfer learning with convolutional neural networks (CNNs), compares ResNet-18 and DenseNet-121, and can withhold a prediction when the model score is below a fixed threshold.
Important: Ray Verify is a research screening aid. It is not a medical diagnostic tool, an authenticity certificate, a fraud detector, or a replacement for source documentation and human review. A model prediction does not prove an image's true origin.

## Project motivation
Medical-imaging research datasets may contain images from different sources and acquisition processes. As generative AI becomes more capable, research data curators may need additional screening tools to identify images that appear synthetic before including them in a dataset.

Ray Verify explores whether supervised image classification can provide a useful first-pass estimate of image origin. It is designed around a curator workflow: the user supplies an image, the model returns an estimated class and score, and uncertain cases are referred for human review.

The project focuses on image-origin screening rather than disease classification. It does not attempt to identify abnormalities, diagnose patients, or assess clinical image quality.

## What the system does
At a high level, the prototype:
1. Accepts a chest X-ray image.
2. Converts it to grayscale and applies the same deterministic input transformations used during evaluation.
3. Passes the image through an ensemble of five fold-specific models.
4. Averages the class scores from the ensemble.
5. Applies a withholding threshold of 0.80.
6. Returns Patient-acquired, Synthetic, or Uncertain.
7. Presents the result through a Gradio interface so a curator can decide what to investigate next.
The notebook contains model training and evaluation workflows for both ResNet-18 and DenseNet-121. DenseNet-121 is the selected model for the current prototype based on the reported comparison.

## Scope and labels
The implemented classification task contains two ground-truth classes:
Label	Meaning
0	Patient-acquired chest X-ray
1	Synthetic chest X-ray


Uncertain is not a third ground-truth dataset class. It is an operational model outcome: the system withholds a definitive class when the maximum ensemble score is below 0.80.

The earlier proposed mixed/AI-edited class and secondary image attributes are outside the final implemented scope. The project uses existing Kaggle collections; images were not generated by the project developer.

## Data preparation
The notebook includes the following data-preparation stages:
1. File discovery and readability checks: image files are discovered from the patient-acquired and synthetic folders and opened with Pillow. Unreadable files are recorded by the relevant checks.
2. Image inventory: image dimensions and other basic image information are inspected.
3. Synthetic image conversion: JPEG/JPG images in the synthetic working folder are converted to PNG where needed. The conversion cell skips a PNG if it already exists.
4. Grayscale standardization: synthetic PNG images are converted to grayscale and padded/resized to 256×256.
5. Exact duplicate checks: the notebook computes SHA-256 hashes over image dimensions and decoded RGB pixel bytes, identifies repeated image content, and removes duplicate copies from the working folders.
6. Metadata creation: a CSV records image path, source URL, download date, origin label, label status, provenance evidence, processing state, and quality status.
7. Model input selection: top-level PNG files are selected for the model split.
8. Train/test split: the selected image paths and labels are divided using a stratified 80:20 split with random_state=42.
The original image files should remain preserved separately. Converting a JPEG to PNG does not restore information lost during JPEG compression. Also, 256×256 = 65,536 is the number of pixels in a 256×256 image; it is not a common pixel-intensity value.

## Model preprocessing
For pretrained ImageNet architectures, images are transformed to three channels and processed using the selected Torchvision weights' evaluation transforms. The training transform adds a small brightness variation using ColorJitter(brightness=(0.95, 1.05)). Validation and test transformations are deterministic and do not apply random augmentation.

The model input shape is 3 × 224 × 224.

## Model development
Two pretrained CNN architectures are compared:
ResNet-18
ResNet-18 is the baseline architecture. Its pretrained ImageNet feature layers are frozen in the recorded model-building code, and the final fully connected layer is replaced with a two-class output layer.
DenseNet-121
DenseNet-121 is the comparison architecture. It uses pretrained ImageNet weights and a replacement classifier for the two origin classes. Five fold-specific models are trained and their output scores are averaged for ensemble inference.

## Evaluation methodology
The final comparison uses the same independent test manifest for ResNet-18 and DenseNet-121. The reported test set contains 2,521 images: 1,264 patient-acquired and 1,257 synthetic.

The evaluation reports:
- Precision: among images predicted as a class, the proportion matching that class's dataset label.
- Recall: among images belonging to a class, the proportion correctly identified.
- F1-score: harmonic mean of precision and recall.
- Coverage: proportion of images receiving a definitive class rather than Uncertain.
- Error among classified: incorrect definitive predictions divided by all definitive predictions.
- Uncertain count: number of images withheld from definitive classification.
The 0.80 threshold is applied to the maximum ensemble class score. If the maximum score is below 0.80, the model returns Uncertain. These model scores are not established as calibrated probabilities of correctness.

## Uncertainty and human review
The interface uses a fixed threshold of 0.80:
- If the maximum ensemble score is at least 0.80, the image receives the class with the higher score.
- If the maximum ensemble score is below 0.80, the result is Uncertain.
The purpose of withholding is to avoid forcing a class label when the model's score is below the selected threshold. An Uncertain result should be reviewed using source records and other available provenance evidence. The model does not automatically approve or reject images for a research dataset.

## Explainability, fairness, and robustness
## LIME explainability
LIME was applied to DenseNet-121 to generate a local, superpixel-based explanation for an individual image. The recorded experiment used 1,000 perturbation samples. LIME highlights regions that influence the model's local prediction; it does not prove that the model relies on medically meaningful features or that the prediction is correct.
## Fairness exploration with AIF360
AIF360 was explored, but a meaningful group-fairness audit could not be completed because the dataset does not contain independent protected attributes or demographic group information. The image-origin label is the prediction target and must not be reused as a protected attribute for a group-fairness claim. Therefore, no valid group-fairness conclusion is reported.
## FGSM adversarial robustness
DenseNet-121 was stress-tested using the Fast Gradient Sign Method (FGSM) with epsilon = 8/255. The recorded clean test accuracy was 98.73%, while accuracy on FGSM-perturbed images was 43.79%, a decrease of 54.94 percentage points. This indicates substantial sensitivity to adversarial perturbations. The result is a robustness warning, not evidence that the system is secure against all attacks.

## Known limitations and risks
1. Synthetic source permissions: the synthetic Kaggle notebook describes a generation method but does not provide explicit usage permission or complete original-source provenance.
2. Patient-level leakage: patient and study identifiers are unavailable, so patient-level or study-level overlap between training and test data could not be verified. The split is image-level and stratified.
3. Dataset representativeness: the models were trained and evaluated on two specific Kaggle collections. Source-specific artifacts may influence predictions, and unseen generators may behave differently.
4. Count reconciliation: downloaded, metadata, and model-input counts come from different pipeline stages and file-discovery rules. Recompute the source-wise inventory for the exact run before reporting a final reconciliation.
5. Fairness: demographic/protected attributes are not available, preventing a meaningful group-fairness audit.
6. Adversarial sensitivity: FGSM testing showed a large reduction in accuracy.
7. Score calibration: the 0.80 threshold is a fixed operational threshold; model scores have not been established as calibrated probabilities.
8. External validation: no independent external dataset from a separate institution or unseen generator is included in the reported comparison.
9. Latency and memory: exact end-to-end latency and memory consumption were not measured in the reported experiments.

## Responsible use
Ray Verify should only be used as an experimental screening aid by people who understand its limitations. A model output must not be treated as proof that an image is genuine or synthetic. Curators should verify source documentation, applicable permissions, and provenance independently. Uncertain cases and cases with important consequences require human review.

Do not use Ray Verify for diagnosis, treatment decisions, patient triage, clinical decision-making, or automated rejection of research images. Do not upload identifiable medical images to an unapproved hosted service. Follow the data provider's terms, institutional policies, and applicable privacy requirements.

- Reconcile source-wise counts from original downloads through cleaning, metadata generation, and model input selection.
- Execute and verify a complete image-level lineage manifest with file hashes and split/fold membership.
- Obtain patient/study grouping metadata where permitted and evaluate group-based splitting to reduce related-image leakage risk.
- Evaluate on an external dataset and on synthetic images from generators not represented during training.
- Add calibration analysis and justify the withholding threshold using development data without tuning on the independent test set.
- Investigate stronger robustness methods and evaluate additional attacks.
- Measure inference latency, peak memory, and throughput on documented hardware.
- Conduct a meaningful fairness evaluation if appropriate independent group attributes become available.
- Perform a curator-focused usability evaluation of the Gradio workflow.
